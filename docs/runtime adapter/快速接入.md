# Runtime Adapter 快速接入（v0.1）

跨语言宿主通过 **gRPC** 调用 echo-agent；契约以 `echo_agent/adapter/proto/echo_agent.proto` 为准。  
完整设计见同目录 [runtime adapter v0.1.0 设计文档](./runtime%20adapter%20v0.1.0%20设计文档.md)。

---

## 1. 启动服务

```bash
# 在 echo-agent 仓库根目录（已安装本包依赖）
# 默认绑定 127.0.0.1:50051；跨机需显式 --host，并由宿主终止 TLS/鉴权
uv run python -m echo_agent.adapter.grpc.server \
  --factory examples.integrator_runtime.build_agent:build_agent
```

服务：`echo_agent.v1.EchoAgentService`  
默认监听：`127.0.0.1:50051`（insecure；可用 `--host` / `--port` 修改）

---

## 2. 宿主侧准备

1. 拷贝 `echo_agent/adapter/proto/echo_agent.proto`（不要复制整个 Python 库）
2. 用各语言 gRPC 工具生成 Client（C# / C++ / Java / Go / Python 均可）
3. 连到上一步的地址

Python 本机依赖本库时，也可：

```bash
pip install -e /path/to/echo_agent
```

---



## 3. 调用顺序

```text
CreateAgent(AgentConfig) → agent_id
宿主自管 session_id（多轮 / HITL 必填，映射 thread_id）
Invoke 或 Stream(agent_id, session_id, UserInput)
若 interrupted → 收集人机结果 → Resume 或 StreamResume
运行中可随时 Cancel(agent_id, session_id) 中止当轮
业务结束 → DeleteAgent(agent_id)
```


| RPC                       | 说明                                 |
| ------------------------- | ---------------------------------- |
| `CreateAgent`             | 调用注入 factory 创建 Agent，返回 `agent_id` |
| `DeleteAgent`             | 销毁进程内 Agent 实例（业务结束时由宿主调用）      |
| `Invoke`                  | 同步一轮，返回 `AgentResponse`            |
| `Stream`                  | 流式事件 `AgentEvent`                  |
| `Resume` / `StreamResume` | HITL 恢复；`values_json` 为 JSON 对象字符串 |
| `Cancel`                  | 中止当轮图执行（非 HITL `{"cancelled":true}`） |

{

## 5. Invoke / Resume 要点

**InvokeRequest**

- `agent_id`：CreateAgent 返回值  
- `session_id`：宿主会话 ID（必填）  
- `input.text`：用户文本；`attachments` 可选（v0.1 仅 text 进模型）  
- `metadata`：可选 `map<string,string>`，透传到 `RunnableConfig.configurable["metadata"]`（见下）

**ResumeRequest** 同样可带 `metadata`（语义同 Invoke）。

**metadata 约定**

- 宿主与集成方自行约定键；echo-agent **不解释**业务键（如 `user_id` / `tenant_id`）。  
- **保留键 `http_headers`**：值为 **JSON object 字符串**（如 `{"Authorization":"Bearer xxx"}`）。入口校验后解析为 `dict[str, str]`，写入 `configurable["metadata"]["http_headers"]`，供图节点 / 出站 HTTP 使用。  
- 非法 `http_headers`（非 JSON、非 object、或非 string 条目）→ `INVALID_ARGUMENT`。

示例：

```json
{
  "agent_id": "...",
  "session_id": "sess-1",
  "input": { "text": "hello" },
  "metadata": {
    "trace_id": "abc",
    "http_headers": "{\"Authorization\":\"Bearer xxx\"}"
  }
}
```

节点内读取：

```python
meta = (config.get("configurable") or {}).get("metadata") or {}
headers = meta.get("http_headers") or {}  # 已是 dict[str, str]
```

**AgentResponse**

- `output`：最终回复文本  
- `interrupted=true`：停在 HITL，读 `interrupt_json`  
- 恢复时 `ResumeRequest.values_json` 示例：

```json
{"approved": true}
```

或信息补全：

```json
{"values": {"city": "上海", "date": "2026-07-24"}}
```

（具体字段以当时 `interrupt_json` 为准。）

## 6. Cancel（中止当轮）

用于前端「停止」：**只停当前这一轮** Invoke / Stream / Resume / StreamResume，不删 Agent、不换 `session_id`。

**与 HITL 取消的区别**

| | `Cancel` RPC | HITL `Resume` + `{"cancelled":true}` |
|--|--|--|
| 时机 | 图正在跑 / 正在流式输出 | 已停在 interrupt，等人机 |
| 效果 | `task.cancel()` + tip 回滚到开跑前 checkpoint | 继续图，走 cancelled 状态机 |

**CancelRequest**

- `agent_id` / `session_id`：必填  

**CancelResponse**

- `cancelled=true`：当时有活跃 turn，已发出取消并回滚  
- `cancelled=false`：当时无活跃 turn（幂等成功）  

**宿主推荐做法**

```text
用户点停止
  →（若在 Stream）取消当前 Stream RPC
  → 再调 Cancel(agent_id, session_id)   // Invoke 必靠这条；Stream 作双保险
  → UI 结束 busy；同 session 可立即发下一轮
```

- 断流时服务端也会走同一取消路径（回滚 checkpoint）。  
- 同一 `agent_id` + `session_id` **同时只允许一轮**；并发第二轮 → `FAILED_PRECONDITION`。  
- 被 Cancel 中止的 Invoke/Stream：gRPC status 为 **`CANCELLED`**（不是 `INTERNAL`）。

---



## 7. Stream 事件（最小集合）

`AgentEvent.type` + `data`（UTF-8 JSON bytes）。

事件顺序：`message*` → 以 `interrupt` | `done` | `error` | `cancelled` 之一收尾。


| type        | 含义                                               |
| ----------- | ------------------------------------------------ |
| `message`   | 模型/消息片段，如 `{"role":"assistant","content":"..."}` |
| `interrupt` | HITL 挂起，payload 同 interrupt 语义                   |
| `done`      | 正常结束，如 `{"output":"..."}`                        |
| `error`     | 错误，如 `{"message":"...","type":"..."}`            |
| `cancelled` | 当轮被中止（Cancel RPC 或断流）；随后 RPC status=`CANCELLED` |


可选还会出现 `tool_result`（非必须处理）。

**失败契约（与 Invoke 对齐）**：出现 `error` 事件后，`Stream` / `StreamResume` 的 gRPC **status ≠ OK**（`INTERNAL`）。客户端应同时：

1. 消费流中的 `error.data`（结构化详情）  
2. 以 RPC status 做失败判断（勿仅因「流结束」当作成功）

**取消契约**：出现 `cancelled` 或断流 / `Cancel` 后，status 为 **`CANCELLED`**；checkpoint tip 已回滚到开跑前，勿把半截 `message` 当正式终态。

---



## 8. 注意

- **默认仅绑定回环**：库 / CLI 默认 `host=127.0.0.1`，避免误暴露公网；需要跨机时显式 `--host 0.0.0.0`（或 `[::]`），并在宿主侧做网络隔离 + TLS/鉴权（Adapter 本身为 insecure）  
- **不提供** CreateSession / DeleteSession；`session_id` 由宿主管理  
- **提供** `DeleteAgent`：销毁进程内 Agent（含 Memory checkpointer 等随实例释放）；可选 `AgentRuntime(max_agents=N)` 作数量护栏（超额 Create → `RESOURCE_EXHAUSTED`）  
- **提供** `Cancel`：中止当轮执行并回滚 tip；见 §6（勿与 HITL `{"cancelled":true}` 混淆）  
- 同一 `agent_id` + 同一 `session_id` 共享 Checkpoint，才能多轮与 Resume  
- Invoke/Resume 可选 `metadata` → `configurable["metadata"]`；保留键 `http_headers` 见 §5  
- 一阶段工具来自 MCP + Skill；无本地业务 Tool 注册 RPC  
- 详细字段与语义以 **proto** 与设计文档为准
